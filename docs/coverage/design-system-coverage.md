## Kapanış sınırları

- Toplam20 core component Day 136–138'de code/variant/state/keyboard/focus/role/form/error/stories/browser-test sahibidir. Avatar, Dropdown, Accessibility, Documentation, Guidelines gibi tekrarlar ayrı source ID'dir.
- `Spacking` kaynak etiketi aynen korunur; görev gerçek Spacing konusudur.
- DTCG token source ve generated output tek canonical owner'a bağlıdır; Penpot design artifact/code/token version izleri explicit'tir. Token API support gün başında doğrulanır; plugin çalıştırılamazsa label Comparison ile kapatılmaz, gap tutulur.
- Design System ana konusu sadece component library kadar dar değildir: marka/ton/guidelines/governance/pilot/release/adoption süreçleri gerçek artifact ve davranış ile birlikte işlenir.
- Native Desktop/Mobile implementation istisnası sürer; web viewport/RTL/responsiveness native app değildir. Node frontend tooling/SSR rolü değişmez; Java business owner kalır.
- Automated axe/a11y/screenshot pass tam WCAG certification değildir; manuel keyboard/assistive-tech smoke evidence da istenir. Synthetic A/B örneği gerçek kullanıcı/conversion/statistical significance kanıtı değildir.
- Ücretli cloud/SaaS/model API, Chromatic veya paid editor/plugin zorunluluğu yoktur. Ücretsiz local ürün/API erişimi yoksa açık gap/çözüm sahibi raporlanır; sessiz hosted/paid fallback yoktur.

Day 143 final raporda technical runtime, Case Applied, Comparison, Partial, Design Only ve access gap ayrı sayılır. Emlak plan satırı uygulama kanıtı değildir; mevcut iki projeden birinde aynı gerçek doğrulanmış kanıt yeterliyse yeniden kullanılır.
