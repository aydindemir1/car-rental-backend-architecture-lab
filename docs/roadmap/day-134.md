## Öğrenme ve uygulama görevleri

1. Day 88 token baseline'ını genişlet. Raw/reference, semantic ve component alias seviyelerini ayır; bir Git-versioned JSON kaynağı canonical token owner olsun.
2. Style Dictionary ile DTCG uyumlu seçilmiş formatı CSS custom properties/TS çıktısına dönüştür. Format edition ve tool compatibility uygulama gününde pin edilir; DTCG Community Group raporu W3C Recommendation diye sunulmaz.
3. Colors: Functional Colors, Accessibility, Dark Mode ve Guidelines için success/error/info/focus/surface/text token'ları kur. Status yalnız renk ile anlaşılmaz; text/icon desteği ve contrast sözleşmesi ekle.
4. Theme alias resolution, unknown reference, cyclic alias, invalid type ve missing token failure testleri yaz. Generated code elle ikinci canonical kaynak olmaz; build/diff drift kontrolü çalışsın.
5. Layout: Units, Grid, Breakpoints ve kaynakta 'Spacking' diye yazılmış Spacing konusunu ölçü sistemiyle uygula; rem/px/% seçim koşulları ve logical CSS properties kullanımı açık olsun.
6. Dar/geniş viewport, browser zoom, uzun metin ve RTL fixture'larında reflow/overflow, grid gap ve spacing davranışlarını test et. Desktop/mobile web viewport testi native app geliştirme değildir.
7. Light/dark/preferred theme değişiminde theme persistence/fallback ve SSR hydration sınırını mevcut frontend profile'da doğrula; token breaking change'in tüketici üzerindeki etkisini kaydet.
