## Öğrenme ve uygulama görevleri

1. Project Management / Task Management: Roadmap, Milestones ve Ticketing için RFC/component change request'lerini Git-versioned backlog/issue-template fixture'ında acceptance criterion/owner/dependency/status'a bağla; dış kişiye task/mesaj atama otomatik değildir.
2. Analytics / Component Analytics: AST/source import inventory ile component adoption/duplicate/raw-style kullanımını say; package version consumers ve token drift raporu üret. İsim bazlı grep gerçek runtime kullanımının tamamı değildir.
3. Tooling Analytics: local token/story build duration, test flakiness, release lead time ve component change failure ölçülerini mevcut CI output'undan türet; sahte ekip productivity ranking'i üretme.
4. Logging ve Service and Health Metrics: design catalog static server, editor/plugin ve Spring pilot API için request/error/availability/latency, build health ve bounded log collection'i mevcut telemetry altyapısına bağla. UI component kendi başına backend service değildir.
5. Runtime pilot analytics event'lerini minimize et; secrets/PII/form input kaydetme. Synthetic event dataset ve retention/cleanup contract'ı kullan; ücretli analytics SaaS zorunlu değil.
6. Communications: Community Meetings, Communication Channel, Open Hours ve FAQs için local repo discussions/proposal/office-hour workshop artifact'ı oluştur. Solo çalışmada role simulation, agenda, feedback rubric, decision ve revision gerçek belgelere bağlı olsun; sahte external participant veya meeting gönderme yok.
7. Bir katkı/RFC ve breaking token release senaryosunda governance/ticket/communication/adoption/evidence döngüsünü tamamla; teknik ölçüm ile eğitim management case evidence'ını ayrı raporla.
8. Stale catalog/failed token build/bad component release hipotezini kontrollü fixture ile dene; rollback/upgrade docs ve recovery ölçüsünü kaydet.
