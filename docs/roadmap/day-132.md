Durum: **Planlandı**. Eğitim milestone'ıdır; birden fazla takvim gününe yayılabilir. Bugün code/runtime evidence oluşturulmuş değildir.

[Day 131](day-131.md) kapanır; önceki birikimli implementation snapshot'ından `day/132` türetilir. [Design System ortak planı](../DESIGN-SYSTEM-ROADMAP-EXTENSION.md), [kapsam matrisi](../coverage/design-system-coverage.md) ve [uygulama sözleşmesi](../coverage/mandatory-implementation-contract.md) geçerlidir.

Native Desktop/Mobile, Node business-backend ve önceki paid cloud/SaaS/model API sınırları yeniden açılmaz.

## Öğrenme ve uygulama görevleri

1. Day 88'in gerçek implementation snapshot'ını incele. Design system, component library ve UI kit ayrımını token+kod+guideline+governance+adoption örnekleri üzerinden açıkla; sadece button paketi tüm design system değildir.
2. What is a Design System, Need of Design System, Atomic Design ve stakeholder sorumluluklarını kiralama akışına bağla. Atoms/molecules/organisms/templates/pages etiketlerini mevcut ekran ağacına uygula; ayrı runtime library kurmak şart değildir.
3. Component, Component Library, Design Language, Governance, Guidelines, Pattern, Pilot, Token ve UI Kit için Türkçe sözlük oluştur; her terimi proje artifact'ına veya ilerleyen günün gerçek görevine bağla.
4. Design System Examples için Material Design, Carbon ve GOV.UK primary kaynaklarından seçilmiş üç davranış/karar örneğini incele. Üç ürünün hepsini portal dependency'si yapma; kaynak/lisans/sürüm ve karşılaştırma sınırını kaydet.
5. Existing Design Analysis / Performing a Visual Audit: Day 88/83/94 mevcut UI üzerinde screenshots, CSS/token tekrarları ve state farkları envanteri çıkar. Icons, Visual Forms, Sizing, Spaces, Color ve Typography için önce/sonra karşılaştırma fixture'ı hazırla. Visual Forms için shape/corner radius/border/elevation; Sizing için control/icon/container ölçüsü örneklerini gerçek CSS/browser fixture'ında göster.
6. Identify Components: Avatar, Badges, Banners, Buttons, Cards, Dropdowns, Forms ve other başlığına projenin ihtiyaç duyduğu table/date selector gibi açık örnekler koy; mevcut/eksik/duplicate/different-state satırlarını kaydet.
7. Identify Existing Design Process: requirement→tasarım→review→kod→test→release izini actual repository artifact'larıyla çıkar. Tek kişi çalışıyorsa roller eğitim simülasyonudur; dış kişilere mesaj/toplantı gönderilmez.
8. A/B Tests & Experiments, Regional Requirements ve Documentation için audit checklist'ine açık pilot kabul kriterleri koy; actual deney Day 141'de, süreç ve ölçümler Day 142'de tamamlanır.
