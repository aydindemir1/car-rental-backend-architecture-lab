## Öğrenme ve uygulama görevleri

1. Day 07 build standardı ve Day 103 TDD/OOP örneğinden sabit bir quote/inspection fixture seç. Önce davranış karakterizasyon testlerini yaz; iyi/kötü örnekler aynı beklenen sonucu üretmeli.
2. Be consistent; meaningful names over comments; indentation/code style: formatter ve review kuralları koy. Yanıltıcı ismi düzelt; 'neden' bilgisini taşıyan gerekli yorumları silme.
3. Keep methods/classes/files small ve minimize cyclomatic complexity: uzun karar ağacını anlamlı responsibility/policy sınırlarına böl. Önce/sonra complexity ve okunabilirlik ölç; satır sayısı tek kalite ölçütü değildir.
4. Pure functions ve effect boundary: fiyat hesabını clock/DB/HTTP side effect'ten ayır, deterministik edge-case testleri ekle.
5. Avoid passing nulls/booleans ve use correct constructs: belirsiz flag parametresini enum/value object'e dönüştür; optional/absent durumuna açık contract ver. Her boolean veya null kullanımı evrensel hata değildir; örnek bağlamında gerekçe yaz.
6. Keep framework code distant ve organize code by actor it belongs to: domain/application kodundan Spring/JPA taşımasını kaldır; burada actor değişiklikten sorumlu iş rolüdür, Pekko actor runtime değildir.
7. Command query separation için mutating command ile read-only query'yi ayrı imzalarla göster. Bu CQS ilkesidir; ayrı datastore/broker gerektiren CQRS olduğu iddiası yoktur.
8. Fast/independent tests için unit test clock/randomness/shared state'i kontrol et, test sırasını değiştirerek izolasyon doğrula. Gerçek DB/contract testini hız adına fake unit testle değiştirme. Küçük refactor/review/regression döngüsünü kaydet.
