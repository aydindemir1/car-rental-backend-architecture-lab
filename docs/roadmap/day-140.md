## Öğrenme ve uygulama görevleri

1. Tooling/Design: ücretsiz local çalışma sınırı için Penpot self-hosted Docker profile seç. Başlangıçta BOM/image/API/resource/license compatibility kontrol et; ücretsiz kaynak erişimi yoksa explicit gap bırak, hosted billing'e fallback yapma.
2. Design Editor'da gerçek frame, layout, shared component/UI kit ve token-bound theme örnekleri oluştur; design file export/source artifact'ını version kontrolüne bağla.
3. Plugins alt başlığını gerçek küçük local TypeScript Penpot plugin'iyle uygula: izinli selection/component metadata'sını okuyup naming/token diagnostic üretsin. Supported plugin/token API uygulama gününde doğrulanır; token API yoksa supported component API fixture'ı ve explicit limit kaydedilir.
4. Plugin manifest/permission/lifecycle ve invalid selection/failure/cleanup testleri yap; yalnız local editor/lab origin, dummy design data kullan. Ücretli plugin/API/model entegrasyonu veya dış service token'ı şart değildir.
5. Version Control için exported design artifact, canonical token JSON, code/component version ve preview diff ilişkisini kaydet. Native editor history, Git text diff ve opaque file snapshot farkını göster; opaque export'u meaningful text diff diye sunma.
6. Contribution Guidelines: tasarım değişikliği→proposal→review/revision→token/component code→story/test→release zincirini küçük gerçek örnekle uygula.
7. Figma/Sketch gibi bilinen alternatifler fiyat/erişim/export/collaboration/lock-in açısından Comparison belgesinde değerlendirilir; aynı iş için ikinci editör zorunlu kurulmaz ve Figma kullanılmış iddiası yapılmaz.
