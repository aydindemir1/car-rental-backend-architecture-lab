1. Git/GitHub mevcut workflow'unu architecture issue/ADR/review/checkpoint evidence'ına bağla; decision trace ve source/runtime versiyonu arasında link kur.
2. Repo-native markdown issue/backlog/review şablonları veya mevcut GitHub board ile küçük delivery case'ini takip et; architecture decision, blocker ve follow-up kapanış izini oluştur.
3. Slack/Trello/Atlassian için communication/board/wiki/issue responsibility ve export/permission/privacy farkını karşılaştır. Gerçek account erişimi yoksa ürün Comparison kalır; mock tool same-product implementation değildir.
4. Erişim varsa sadece kullanıcının ayrıca yetkilendirdiği workspace/test scope'unda ürün görevi yapılır; başkalarına mesaj/invite otomatik gönderilmez. Ücretsiz erişim/trial şartları günü geldiğinde kontrol edilir.
5. Tools'un roadmap'teki iki occurrence'ını ayrı ID ile koru; aynı verified repo workflow evidence'ı shared responsibility'yi karşılayabilir.
6. Tool seçimiyle method/process seçimini ayır; bir tool install architecture karar kalitesi veya ekip deneyimi kanıtı değildir.
