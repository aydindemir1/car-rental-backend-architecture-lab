## Öğrenme ve uygulama görevleri

1. Day 103 DDD fixture'ındaki domain language, invariant ve model ilişkilerini çıkar; UML/class/state modelinden kod/test'e traceability kur. Model-Driven Design burada modeli koda bağlayan tasarımdır; araçla otomatik code generation veya tam MDA yapılmış sayılmaz.
2. Class Variants: concrete class, abstract class ve interface ile farklı extension contract'larını göster; aynı sırf adlandırma örneğini üç kez çoğaltma. Abstract sınıfın instantiation engeli ve interface'in implementer contract'ı görünür olsun.
3. Scope/Visibility, encapsulation ve abstraction: aggregate mutation'ını public setter'dan guard edilmiş davranışa taşı; package/module sınırını compile/ArchUnit ile denetle.
4. Inheritance ve polymorphism için substitution contract'ını test et; inheritance'a alternatif composition profili kur. Beklenmeyen subtype behavior deliberate fixture'da contract testini kırmalı.
5. Domain Models ve Domain Language: booking/inspection terimlerini API DTO, application usecase, domain entity/value object ve persistence model arasında doğru taşı.
6. Anemic Model ile rich Domain Model'i aynı bounded değişiklik üzerinde karşılaştır: invariant kaçıran bad fixture ve düzeltilen davranış testi. Basit CRUD için Transaction Script tercihi otomatik anti-pattern değildir.
7. Layered Architectures dependency yönünü Day 09/104 üzerinden gerçek code/dependency testine bağla; business policy'nin framework detayına bağımlı olduğu deliberately broken fixture kapıyı kırsın.
8. Model/code drift change request'ini çöz; UML güncellemesi tek başına implementation değildir. Mevcut verified code yeterliyse aynısını yeniden kurmadan SHA ve eksik deneyleri bağla.
